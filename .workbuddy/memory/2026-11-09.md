# 2026-11-09

## 部署方式：本机构建 + 服务器只运行

目标机器 2C2G（x86_64），开发机 macOS arm64。原 `deploy/docker-compose.yml` 三容器方案保留。

### 新增文件

- `deploy/Dockerfile.pack`：只做 COPY（web 静态页 + linux/amd64 Go 二进制），无编译步骤，构建几秒完成。
- `deploy/build.sh`：本机原生编译 → 打包 amd64 镜像 → `docker save` 出 `deploy/dist/gym-images.tar`（约 42MB）。

### 关键决策与坑

- Apple Silicon 直接 `docker build` 产出 arm64，服务器会 `exec format error`；`--platform linux/amd64` 走 QEMU 编译 node 工具链又慢又易崩。故拆成「原生编译产物 + 纯 COPY 打包」。
- 镜像 tag 必须是 `self-reliant-gym-backend-api:latest` / `-web:latest`（compose 由 `name` + service 推导），否则 `up -d` 会重新 build。用 `docker compose config --images` 可核对。
- `docker compose up -d` 不要带 `--build`，否则无视已 load 的镜像。
- 本机 Docker Desktop 的 `~/.docker/daemon.json` 里三个加速器（ustc / 163 / baiduce）全部失效，docker.io 直连也超时。workaround：`docker pull --platform linux/amd64 docker.1ms.run/library/<img>` 后 `docker tag` 回标准名。未改动全局配置。
- `deploy/nginx.conf` 依赖 compose 网络里的 `api` 主机名，单独 `docker run` 会因 `host not found in upstream` 启动失败，需 `--add-host api:127.0.0.1` 才能冒烟测试。
- 脚本里 `$TAR，` 这种变量紧跟中文全角标点会被 bash 当成变量名一部分，`set -u` 下直接报 unbound，必须写 `${TAR}`。

### 验证结果

冒烟测试通过：首页 200、SPA 路由回退 200、静态资源正常、`/api` 反代在无后端时 502（符合预期）。镜像 `api=amd64/linux 20MB`、`web=amd64/linux 26MB`。

### 尚未做

- 服务器 2C2G 的 MySQL 内存调优（`performance_schema=OFF`、容器 mem_limit、swap）未实施。
- HTTPS / 域名 / 证书层未配置，`docker-compose.yml:34` 仍绑 `127.0.0.1:18080`。
- 数据库是否迁到托管版暂缓，先同机跑。用户倾向「先省钱，有真实用户再拆」。

## 2C2G 内存调优（当日补做）

`deploy/docker-compose.yml` 加了 mem_limit：mysql 640m / api 128m / web 64m，合计上限 832MB，配 350MB 宿主开销后留 800MB 缓存。

MySQL `command` 参数（**`mysqld` 必须写在第一位**，因为官方镜像 command 会整体替换 `CMD ["mysqld"]`）：
- `--performance-schema=OFF` —— 实测常驻 **197MB**，默认约 450MB，省 250MB，是最大头
- `--innodb-buffer-pool-size=128M`、`--max-connections=50`、`--skip-name-resolve`

实测验证：启动 6s，参数全部生效，`gym` 用户走 TCP 能连通，默认字符集 utf8mb4。

新增 `deploy/server-init.sh`（幂等，仅 Linux）：建 2G swapfile 写 fstab（已有则跳过）+ `vm.swappiness=10`。理由：默认 60 会提前把 InnoDB buffer pool 换出，延迟从毫秒跳到几十毫秒。

排障提示：`docker stats` 里 mysql 长期贴 640m 上限 = 该拆库了。

## 新增 deploy/publish.sh（一键发布）

`./deploy/publish.sh user@host [--path /opt/gym] [--config] [--skip-build]`

流程：连通性检查 → 调 build.sh → `mkdir -p $REMOTE_PATH/deploy` → scp tar → docker load → compose up -d（不带 --build）→ ps + docker stats。

设计取舍：
- **默认不传 `.env`**，避免开发机测试口令覆盖服务器生产密钥；缺失时报错并提示 `--config`。
- 只用 scp + ssh，不用 rsync，服务器零额外依赖。
- 只传镜像 tar，服务器不需要源码（compose 有 build 段但镜像存在时不会触发构建）。

踩坑记录：
- **shell 脚本里 `$VAR` 紧跟中文全角标点会被 bash 当成变量名一部分**，`set -u` 下报 unbound。build.sh 和 publish.sh 各踩一次，必须写 `${VAR}`。以后写这类脚本统一用花括号。
- `scp` 到 `$REMOTE_PATH/deploy/docker-compose.yml` 前必须先建 `deploy/` 子目录，否则 No such file。
- macOS 没有 `timeout` 命令，测试网络失败用 TEST-NET 地址（192.0.2.1）比 timeout 可靠。

未做：`--path` 含空格时的 scp 远程路径转义（目前不处理，文档要求绝对路径即可）。

# 撸铁不求人 · 运营后台与后端设计方案

## 一、首版边界

本仓库交付运营人员使用的 Web 后台和一套 Go API。运营人员在浏览器维护资料、发布训练模板、查询会员并处理权益；微信小程序读取同一套已发布内容、订单和权益数据。官方模板、个人计划和训练快照分别存储，模板更新只影响之后采用该版本的用户。

### 仓库结构与技术选型

按同层 XZchat 的 `apps/frontend/package.json`、`apps/backend/go.mod`、`internal/handler` 和部署配置组织。管理网页与 API 独立构建，原生微信小程序继续放在 `self-reliant-gym` 仓库。

| 本仓库规划路径 | 技术与用途 |
| --- | --- |
| `apps/frontend/` | React 18、TypeScript、Vite 5、Ant Design 5、React Router 6、Less。依赖用 pnpm 安装并提交锁文件。 |
| `apps/frontend/src/` | `App.tsx` 管理登录态、布局和路由；`pages/` 按运营菜单设页；`api/client.ts` 统一同源请求与错误处理；`model/types.ts` 定义接口类型；`components/`、`styles/` 放共用界面和样式。 |
| `apps/backend/` | Go 1.25、Gin 1.11、GORM 1.31、MySQL 8.4（InnoDB）。`cmd/api` 加载配置、迁移并启动服务。 |
| `apps/backend/internal/` | `config` 读取环境配置；`handler` 注册路由、鉴权和参数校验；`service` 实现发布、开练、支付和权益事务；`repository` 管理数据库连接和查询；`model` 定义实体。 |
| `apps/backend/migrations/` | 编号 SQL 随程序嵌入，使用本项目独立的 MySQL 迁移锁和版本表；迁移失败时停止启动。种子模板只在首次迁移写入，后续运营修改通过后台发布。 |
| `deploy/` | 部署编排集中于此：`Dockerfile` 多阶段一次构建出 web、api 两个镜像；`docker-compose.yml` 运行 Nginx、API、MySQL，构建上下文为仓库根；`nginx.conf` 提供后台静态页、SPA 路由回退并将 `/api/` 转发给 Gin。MySQL 仅在容器网络内可达（`expose`），数据卷持久化，服务就绪后再接流量；容器内 DSN 由服务名 `mysql:3306` 覆盖，宿主机 `go run` 仍用 `.env` 的 `127.0.0.1`。 |

### 运营后台菜单

| 页面 | 操作与生效范围 |
| --- | --- |
| 训练资料 → 部位／器材分类／动作 | 动作资料维护封面图、步骤、常见的错误、部位（胸、背、肩、二头、三头、小臂、腿、小腿、臀部、腹部、斜方肌、有氧）、细分肌群（上胸／中胸／下胸等，叶子部位留空）与器材分类（器械、杠铃、哑铃、史密斯、绳索、弹力带、徒手），具体器材名另填一份供套餐生成匹配。列表按部位、分类、关键词筛选。动作发布须有完整教学和有效关联。下架前列出受影响的已发布模板，先替换动作或下架对应模板，再处理资料。 |
| 训练模板 → 模板列表 | 按名称、每周训练次数、发布状态筛选。支持新建、编辑草稿、预览、发布、下架；可调整小程序首次选择页的展示顺序。列表同时显示线上版本和未发布草稿。 |
| 训练模板 → 周计划编辑 | 设置名称、目标、适用经验、重点部位标签（含全身）、展示顺序；按周一至周日设置训练或休息，为每个训练日指定部位、添加和排序动作、填写目标组数、每组次数、组间休息。周练次数从非休息日推导。预览使用与小程序一致的七日结构。 |
| 会员管理 → 会员列表／详情 | 按用户 ID、商户订单号、会员状态和到期区间查询。详情展示有效期、关联订单、支付与人工权益流水；对从未开通过的用户也能按 ID 定位并人工发放。 |
| 会员管理 → 套餐／订单 | 维护三档套餐的展示与上下架；固定期限及初始定价见交易表。订单支持按单号、用户、状态和时间查询，待确认订单可触发渠道查单。 |
| 系统 → 操作记录 | 按操作者、目标和时间查询模板发布／下架、套餐变更、人工权益操作，查看原因和前后值。 |

**模板发布流程。** 保存草稿允许逐步填写。发布时校验至少一个训练日、每个训练日有部位和动作、关联资料可用、组次为正整数、休息为 30／60／90 秒。每个模板有稳定 ID、一个线上版本和至多一个编辑中草稿；修改已发布内容时从线上版本复制草稿。保存、发布和下架携带修订号，冲突返回 409。发布事务内冻结草稿、切换线上版本并写审计，小程序列表和详情只读取当前发布版本。下架后停止展示与新采用，既有个人副本和训练记录仍可读取。

**人工权益流程。** 运营可查询会员与订单；管理员可在会员详情选择发放天数或撤销指定人工发放记录，填写原因，确认前查看预计到期时间。提交时携带操作编号和权益版本，过期版本需刷新后确认。同一用户的人工调整、支付到账和退款共用权益服务，在同一事务锁定用户权益、记流水、重算有效期并写审计。支付来源流水的撤销依据渠道退款结果；人工补发与实付订单在详情中分栏展示。

**后台权限。** 参考 XZchat 的后台会话方式，运营身份独立建表。后台使用账号密码、bcrypt 哈希和带有效期及版本号的签名会话；生产 Cookie 设置 HttpOnly、Secure、SameSite=Strict，限定后台 API 路径，写请求校验同源。首个管理员由部署配置初始化；停用、改密后旧会话失效。运营员可维护资料和模板、查看会员订单，管理员另有套餐管理、人工权益调整及全量审计权限。Gin 对每个后台路由校验身份和权限，前端按同一权限展示菜单。小程序凭证仅用于用户接口，PRO 有效期仅决定智能生成权益。

## 二、数据关系与约束

主键由服务端生成；API 中的长整型 ID 按字符串传输。时间戳统一存 UTC，训练归属日按开始时的北京时间固化，周一为一周起点。个人数据均带用户归属，读写以登录身份校验。

| 数据表 | 核心字段与约束 |
| --- | --- |
| users | id、app_id、openid、experience_level（未选／小白／训练老炮）、active_plan_id。微信身份组合唯一，当前计划指向自己的计划版本。 |
| muscles、exercises、equipment | 肌群名称；动作名称、部位、细分肌群、器材分类、具体器材名、准备姿势、步骤、常见错误、图示、发布状态；器材名称、调节方法、使用步骤、图示、发布状态。部位与细分建组合索引供动作库侧边栏查询。内容下架后保留历史引用。 |
| exercise_muscles | 动作、肌群、作用（主要／辅助）；动作与肌群组合唯一。发布时至少指定一个主要肌群。 |
| exercise_equipment | 动作、器材组合号、器材；三者组合唯一，另建器材反查索引。同组合的器材须同时满足，组合间可替代；徒手由动作字段显式标记。 |
| plans、plan_days、plan_items | plans 区分官方模板、个人计划、生成草案，记录所有者、来源版本。个人计划有稳定的计划库条目 ID，编辑产生同一条目的新版本；列表按条目返回最新版本。训练日保存星期、部位；项目保存动作、顺序、目标组次和休息秒数。周内星期唯一，同一天顺序唯一。 |
| templates | 稳定模板 ID、当前发布版本 ID、草稿版本 ID、修订号及展示顺序。版本内容复用 plans、plan_days、plan_items，模板 ID 与版本号组合唯一；个人副本记录采用的具体版本。 |
| admin_accounts、admin_audit_logs | 后台账号名唯一，保存密码哈希、角色、启用状态、会话版本；审计保存操作者、对象、动作、原因、前后值、请求编号和时间。 |
| training_sessions、session_items | 用户、来源计划和训练日、归属日期、开始／结束时间、状态、版本；项目保存动作 ID、名称、目标肌群、顺序、组次、休息档位及跳过标记。训练中的展示和结算均取快照。 |
| training_sets、training_operations | 已完成组保存项目、组序、实际次数、可空重量（定点公斤数）；项目与组序唯一。操作表以用户和操作编号唯一，保存请求摘要及结果，与业务变更同事务提交。 |
| products、orders | 商品编码、期限、金额（人民币分）、上下架状态。订单冻结商品、天数、金额、用户及渠道，商户单号唯一；渠道与平台交易号组合唯一。 |
| membership_grants、memberships | 每笔权益记录用户、来源（支付／人工）、来源编号、发放时间、天数及撤销信息；来源与编号组合唯一，人工操作另记操作者和原因。每用户一条有效期汇总，带并发版本号。重算时按发放时间和流水 ID 依次叠加全部有效记录。 |

模板采用、手排保存和生成草案采用均校验星期、动作可用状态、正整数组次及休息档位（30／60／90 秒）。采用时复制训练日与动作，编辑时生成个人新版本，事务内切换当前计划。已有训练继续使用原快照。

## 三、核心业务规则

**登录与首次计划。** 游客只访问首页和双库；恢复有效会话后读取本人的经验与当前计划。尚无计划且未选经验时询问身份，已选经验则直接返回对应分支。小白免费筛选模板：周练次数精确匹配，重点部位覆盖所有所选项，「全身」单独匹配全身模板。只返回适合小白且已发布的版本，按运营排序展示；无结果返回空列表。训练老炮可自行编排周计划。

保存时校验模板版本仍在线；若已更新或下架，返回冲突并提示重新选择。事务内复制周结构到用户计划库并切换当前计划，按用户和保存操作编号去重，同编号重试返回原结果；并发更改以当前计划版本校验。保存响应同时返回建议开练的训练日（当天优先，其次为跨周在内最近的下一训练日）。只有用户点击「猛攻」才调用开练接口，已有会话优先恢复。

**开练与监督**

1. 从当前计划选择训练日。服务端锁定用户行；已有进行中的训练则返回该训练及位置，否则在同一事务创建会话与全部目标快照。重复点击、不同设备同时开练均只产生一个进行中会话。
2. 逐组写入实际次数与可选重量。实际次数为正整数，重量非负，组序须落在当前动作的目标范围内。服务端按快照顺序推进，跳过动作只跳过剩余组。训练进度返回已做组数、当前项目及下一组位置。
3. 所有训练写操作提交稳定操作编号；开练后的修改另带预期版本。先识别已处理的相同请求，再校验版本和可操作状态。同编号不同内容或版本过旧返回冲突和当前进度。客户端按序补交，服务端按提交次数记账，不按网络重试次数记账。
4. 结束时按已记组数结算：完成全部目标为“已完成”，完成部分为“提前结束”，零组为“已取消”。终态冻结，时长取结束减开始；断网收尾可提交本地结束时间，需限制在开始与服务端接收时间之间。历史按用户、归属日期和 ID 倒序分页。
5. 训练计划页同时返回目标训练日数、已完成训练日数和当前会话。周进度仅计完整达标的训练日，同周同一星期槽位只计一次；提前结束可查历史。更换计划后，周进度按当前计划的训练星期与本周已完成的目标星期取交集，保留所有历史场次。

**会员智能生成**

首版采用可复核的规则生成器：输入目标、选定训练日、单次时长和可用器材；从维护好的周结构中选择匹配训练天数与目标的结构，按肌群、初学者适用性、器材组合筛动作，结合预设动作耗时与组间休息裁剪到时间预算。内容维护时须配置这些标签与耗时。无法满足条件时返回具体缺口，不编造动作。

生成接口校验服务端有效期并按用户限流，结果写入用户草案，返回逐日部位、动作、组次和时长估算。确认采用才替换当前计划。过期后仍可查看、编辑和执行已保存的个人计划。拍照识别的豆包调用安排在第二期。

**交易与权益**

- 三档均为一次性购买、绑定当前微信账号。客户端仅提交商品编码和下单请求编号，服务端读取商品定价。按实际获准的虚拟商品渠道与终端能力返回可购状态；商户资质、平台商品配置及渠道验证作为开放购买的前置条件。

- 核实到账后锁定订单和用户权益行，在同一事务写入已支付状态、唯一权益流水和新到期时间，续期从当前有效期末与到账时刻中的较晚者起算。核实全额退款后撤销对应流水，按发放顺序重算剩余支付及人工流水，更新汇总。支付密钥仅存服务端，日志对登录凭据与支付材料脱敏。

## 四、前后端接口契约

**小程序与渠道接口**使用前缀 `/api/v1`。肌群、动作和器材列表及详情允许匿名读取。模板、引导状态、个人计划、训练记录、账户和权益接口均校验小程序登录态，未登录返回 401。登录由服务端用微信临时凭证换取账号标识，再签发有期限的业务凭证；客户端凭证过期后重新登录。错误返回业务码、可读信息、请求编号；版本冲突附当前版本。列表统一使用游标分页。

| 方法与路径 | 输入与响应重点 |
| --- | --- |
| POST /auth/wechat | 临时登录凭证 → 业务凭证及有效期 |
| GET /exercises、/exercises/{id}、/categories | 动作列表支持部位、细分、器材分类与名称关键词筛选；详情返回单条教学；`/categories` 返回部位（含细分）与器材分类的约定顺序，小程序侧边栏与后台下拉共用 |
| GET /muscles、/equipment | 名称关键词、肌群或器材筛选 → 列表与下页游标 |
| GET /equipment/{id} | 器材详情含操作说明与关联动作 |
| GET /me；PATCH /me/experience | 读取本人经验、当前计划 ID（可空）；持久化小白或训练老炮选项，重复提交同一选项结果一致 |
| GET /templates、/templates/{id} | 列表支持按经验、每周训练次数、重点部位筛选，详情返回具体发布版本、完整周结构及动作组次；免费开放给已登录用户 |
| GET /plans；GET /plans/{id} | 分页读取本人的个人训练计划库，标识当前使用条目；详情返回该计划的训练日与动作 |
| GET /training/summary | 账户页展示本人本月及累计训练次数和时长，按已完成、提前结束的场次汇总 |
| GET /plans/current；PUT /plans/current | 读取周计划；保存完整手排内容或采用指定模板／草案版本，携带操作编号及预期当前版本（首次为空）；返回个人计划 ID、版本及建议开练的训练日 ID |
| POST /plans/generate | 训练目标、训练日、时长、器材 → 可编辑草案；无有效会员返回 403 |
| GET /training/today | 今日安排、本周完成情况、可继续的会话 |
| POST /sessions；GET /sessions/{id} | 按计划版本与训练日开练；读取当次快照和进度以恢复现场 |
| PUT /sessions/{id}/items/{itemId}/sets/{setNo} | 实际次数、可选重量、操作编号、预期版本 → 已完成组数、下一组、版本 |
| POST /sessions/{id}/items/{itemId}/skip；POST /sessions/{id}/finish | 跳过剩余组或按实际记录结算 → 新进度或终态摘要 |
| GET /sessions | 按日期分页，返回计划组数、实际组数、用时、终态；详情复用会话读取接口 |
| GET /products、/membership | 套餐与可购状态；当前账号的权益及到期时间 |
| POST /orders；GET /orders、/orders/{id} | 幂等创建订单并返回渠道参数；分页查询本人订单或查询单笔到账状态 |
| POST /billing/notifications/{channel} | 支付平台专用入口，按渠道验签，处理支付与退款事件 |

**运营后台接口**使用独立前缀 `/api/admin/v1`。登录外均校验后台会话；后台表格按页码分页，响应包含总数。业务错误包含请求编号，401 返回登录页，403 提示权限不足。

| 方法与相对路径 | 允许角色与用途 |
| --- | --- |
| POST /auth/login、POST /auth/logout、GET /auth/me | 登录、注销、读取当前后台角色与权限 |
| GET／POST /muscles、/equipment、/exercises；PATCH 对应 /{id} | 运营员及管理员维护资料和关联；动作保存时校验部位、细分与器材分类是否属于约定范围；状态变更校验已发布模板、动作的依赖 |
| GET /categories | 返回部位（含细分）与器材分类的约定顺序，后台下拉直接取这份定义 |
| GET／POST /templates；GET /templates/{id}；PUT /templates/{id}/draft | 运营员及管理员查询、新建、查看线上及草稿版本、保存整周草稿 |
| POST /templates/{id}/publish、/templates/{id}/unpublish | 运营员及管理员发布指定草稿版本或下架；展示顺序随发布生效 |
| GET /members、/members/{userId}、/orders、/orders/{id}；POST /orders/{id}/reconcile | 运营员及管理员查询会员和订单、按渠道核对支付状态，复用支付核验与幂等发放流程 |
| POST /members/{userId}/grants、/members/{userId}/grants/{grantId}/revoke | 管理员人工发放或撤销一笔人工权益；校验流水归属、来源、版本与操作编号 |
| GET /products；PATCH /products/{id}；GET /audit-logs | 两种角色可读套餐，管理员修改展示和上下架、查询操作审计 |

## 五、实施顺序和交付口径

| 阶段 | 后端交付 | 完成条件 |
| --- | --- | --- |
| B1 工程与资料库 | 搭建 web、api、mysql，接入后台登录、角色鉴权、审计和资料维护页 | 运营能维护器材与动作，小程序可查已发布资料；普通微信用户无法调用管理接口 |
| B2 计划（依赖 B1） | 周模板编辑器、预览与发布、首批 2／3／4 练模板、账号经验、免费匹配、个人计划库与采用 | 小白按周频及部位获得已发布方案，重复保存只产生一个个人条目；返回的训练日可直接开练 |
| B3 训练（依赖 B2） | 会话快照、逐组幂等、补传、结算、周进度、历史 | 能对照某次训练的计划与实绩；重复请求不增加组数，跨设备可恢复服务端进度 |
| B4 会员（依赖 B2） | 套餐与订单页、会员查询与人工调整、支付核验、生成规则及草案 | 运营可按订单追踪权益；授权调整留痕，重复提交只生效一次；小程序按同一有效期开放智能生成 |
| 第二期：拍摄器材 | 服务端短时接收图片并调用豆包视觉 API，将识别结果映射为已发布器材候选，复用器材与动作关系 | 用户确认后得到可练动作；识别不确定、超时或库中无匹配时返回手动选择入口，处理完成后清理临时图片 |
| 第三期：动作评论 | 评论关联用户与动作，增加待审、公开、驳回／下架状态及举报处理 | 仅审核通过的心得对外可见，危险操作建议可下架；正式教学内容独立维护 |
